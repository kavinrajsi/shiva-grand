# This is NOT the Next.js you know

This version (16.2.6) has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing any code. Heed deprecation notices.

## Stack

- **Next.js 16.2.6** (App Router, Turbopack, React Compiler enabled)
- **React 19.2.4** + **React DOM 19.2.4**
- **JavaScript** (not TypeScript) — `jsconfig.json` with `@/*` → `./src/*`
- **ESLint 9** flat config, `eslint-config-next/core-web-vitals`
- **Tailwind CSS v4** — via `@tailwindcss/postcss`. `src/app/globals.css` imports Tailwind and references `tailwind.config.js` via `@config`. Plugins: `@tailwindcss/forms`, `@tailwindcss/container-queries`. CSS Modules (`*.module.css`) still work for component-scoped styles.
- **Theme tokens** — defined in `tailwind.config.js`: Material Design 3 color system (`primary`, `surface`, `on-surface`, `outline`, etc.), `font-headline`/`font-body`/`font-label` all aliased to Manrope via `var(--font-manrope)`, and custom `borderRadius` (`DEFAULT: 0.125rem`, `lg: 0.25rem`, `xl: 0.5rem`, `full: 0.75rem` — note: `rounded-full` is **not** a circle here).
- **Custom utilities** in `globals.css`: `.botanical-gradient` (brand-green linear gradient), `.material-symbols-outlined` (icon class with variation axes).
- **Fonts**:
  - **Manrope** via `next/font/google` (weights 200–800) → CSS variable `--font-manrope`
  - **Material Symbols Outlined** via `next/font/local` pointing at `node_modules/material-symbols/material-symbols-outlined.woff2` → CSS variable `--font-material-symbols`; use class `.material-symbols-outlined` (defined in `globals.css`) with ligatures, e.g. `<span className="material-symbols-outlined">home</span>`

## Layout

```
src/app/        — App Router routes (server components by default)
  layout.js     — root layout, font variables on <html>
  page.js       — home page
  globals.css   — site-wide styles
public/         — static assets served at /
types/          — AUTO-GENERATED by Next.js; do not edit
  routes.d.ts   — typed routes
  cache-life.d.ts — cacheLife() profile types
  validator.ts  — page/layout export validator
next.config.mjs — Next config; React Compiler turned on here
postcss.config.mjs — Tailwind v4 (`@tailwindcss/postcss`)
eslint.config.mjs — flat config
jsconfig.json   — path aliases for editor + Next codemods
```

## Conventions

- **Path alias**: import via `@/...` (resolves to `src/...`). Use it for anything outside the same directory.
- **'use client'**: only on components that need hooks or event handlers. Pages/layouts are server components by default.
- **No manual memoization**: React Compiler (`reactCompiler: true` in `next.config.mjs`) handles `useMemo`/`useCallback` automatically. Don't reach for them.
- **Fonts**: prefer `next/font/google` over `<link>` tags — self-hosts at build time, no CLS, better privacy.
- **Styling**: Tailwind v4 utilities for layout/spacing/typography by default. Use CSS Modules (e.g. `page.module.css` next to `page.js`) when you need component-scoped styles that don't translate cleanly to utilities.
- **Navigation**: use `<Link>` from `next/link` for internal routes. External links get `target="_blank" rel="noopener noreferrer"`.
- **Images**: use `next/image` for anything served via Next; remote hosts must be added to `next.config.mjs` `images.remotePatterns`.
- **Caching**: Next 16 introduces the `"use cache"` directive and `cacheLife()` profiles (see `types/cache-life.d.ts` for the list). Prefer these over older `unstable_cache`.

## Things to be careful about

- Do not edit anything under `types/` — it's regenerated by `next dev` / `next build`.
- Do not assume Pages Router conventions. There is no `pages/` directory and no `getStaticProps`/`getServerSideProps`.
- Do not add a `'use client'` directive to a page or layout that imports server-only modules.
- `migration/` is gitignored — treat it as scratch space.
- `.env`, `.env.*` are gitignored. Never commit secrets.
